## 2. 数据库设计

游记功能涉及 3 张表，都在 `wolf2w-cloud` 数据库中。

### 2.1 表关系一览

```
ta_note（游记主表）
  ├── id ──→ ta_note_content.id   （1:1，富文本内容单独存）
  ├── dest_id ──→ ta_destination   （关联目的地）
  ├── author_id ──→ ta_user_info   （关联作者）
  └── id ──→ ta_note_comment.note_id（1:N，评论）
```

**为什么把内容拆出来？** 游记列表只需要标题、封面等元数据，不需要加载大段富文本。拆表后列表查询更快。

### 2.2 ta_note（游记主表）

```sql
CREATE TABLE `ta_note` (
  `id`            bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `dest_id`       bigint DEFAULT NULL COMMENT '目的地id',
  `dest_name`     varchar(255) DEFAULT NULL COMMENT '目的地名称（冗余）',
  `author_id`     bigint DEFAULT NULL COMMENT '作者id',
  `title`         varchar(255) DEFAULT NULL COMMENT '标题',
  `summary`       varchar(255) DEFAULT NULL COMMENT '概要',
  `cover_url`     varchar(255) DEFAULT NULL COMMENT '封面图',
  `travel_time`   datetime DEFAULT NULL COMMENT '旅游时间',
  `avg_consume`   int DEFAULT NULL COMMENT '人均消费',
  `days`          int DEFAULT NULL COMMENT '旅游天数',
  `person`        varchar(20) DEFAULT NULL COMMENT '和谁旅游（1亲子 2情侣 3独自 4家庭 5朋友）',
  `create_time`   datetime DEFAULT NULL COMMENT '创建时间',
  `release_time`  datetime DEFAULT NULL COMMENT '发布时间',
  `update_time`   datetime DEFAULT NULL COMMENT '更新时间',
  `is_public`     varchar(20) DEFAULT '0' COMMENT '是否公开 0:否 1:是',
  `viewnum`       int DEFAULT '0' COMMENT '浏览数',
  `replynum`      int DEFAULT '0' COMMENT '回复数',
  `favornum`      int DEFAULT '0' COMMENT '收藏数',
  `sharenum`      int DEFAULT '0' COMMENT '分享数',
  `thumbsupnum`   int DEFAULT '0' COMMENT '点赞数',
  `status`        varchar(20) DEFAULT NULL COMMENT '状态 0:草稿 1:待发布 2:审核通过 3:拒绝',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 ROW_FORMAT=DYNAMIC COMMENT='旅游日记表';
```

> **注意**：历史数据中 `is_public` 字段有 `'1'` 和 `'true'` 两种值，查询时要用 `IN ('1', 'true')` 兼容。`release_time` 全为 NULL，排序时改用 `create_time`。

### 2.3 ta_note_content（游记内容表）

```sql
CREATE TABLE `ta_note_content` (
  `id`      bigint NOT NULL COMMENT '主键（与 ta_note.id 一一对应，非自增）',
  `content` text COMMENT '游记富文本内容',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='游记内容表';
```

**关键点**：`id` 不自增，插入时手动设为 `ta_note.id`，实现 1:1 关联。

### 2.4 ta_note_comment（游记评论表）

```sql
CREATE TABLE `ta_note_comment` (
  `id`         bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `note_id`    bigint DEFAULT NULL COMMENT '游记id',
  `note_title` varchar(255) DEFAULT NULL COMMENT '游记标题（冗余）',
  `user_id`    bigint DEFAULT NULL COMMENT '评论用户id',
  `create_time` datetime DEFAULT NULL COMMENT '创建时间',
  `content`    text COMMENT '评论内容',
  `type`       varchar(20) DEFAULT NULL COMMENT '评论类型 0:普通 1:评论的评论',
  `status`     varchar(20) DEFAULT '0' COMMENT '状态 0:正常 1:禁用',
  `ref_id`     bigint DEFAULT NULL COMMENT '引用回复时，被回复评论的id',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='游记评论表';
```

### 2.5 游记状态流转

## 3. 开发步骤总览

整个游记模块开发分三大步：

```
第一步：搭建模块框架（先把房子盖好）
  ├── 创建 travel-api-note 模块（实体 + Feign 接口）
  ├── 创建 travel-modules-note 模块（Controller + Service + Mapper）
  ├── 配置 pom.xml 依赖
  ├── 配置 application.yml
  ├── 配置网关路由
  └── 注册模块到根 pom.xml

第二步：跑通项目链路（验证房子能住）
  ├── 启动 Nacos + MySQL + Redis
  ├── 启动 travel-note 服务
  ├── 验证服务注册到 Nacos
  └── 验证网关能路由到 note 服务

第三步：按功能逐步实现（往房子里添家具）
  ├── 功能1：游记列表查询（分页 + 筛选 + 排序）
  ├── 功能2：游记详情（聚合内容 + 作者信息）
  ├── 功能3：游记发布与编辑
  ├── 功能4：点赞 / 收藏 / 取消收藏
  ├── 功能5：首页轮播推荐
  ├── 功能6：全局搜索
  ├── 功能7：后台审核管理
  ├── 功能8：游记评论
  └── 功能9：前端路径兼容
```

**`@TableField(exist = false)` 是什么意思？**

告诉 MyBatis-Plus："这个字段不在数据库表里，生成 SQL 时别带上它。" 用于两种场景：
1. 实体类需要临时传参但数据库没这个列（如 `content`）
2. 冗余字段还没来得及加到数据库（如 `authorNickname`）

#### 4.2.5 Feign 远程接口：RemoteNoteService.java

```java
package cn.wolfcode.wolf2w.business.api;

import cn.wolfcode.wolf2w.business.api.domain.Note;
import cn.wolfcode.wolf2w.business.api.factory.RemoteNoteFallbackFactory;
import cn.wolfcode.wolf2w.common.core.constant.SecurityConstants;
import cn.wolfcode.wolf2w.common.core.constant.ServiceNameConstants;
import cn.wolfcode.wolf2w.common.core.domain.R;
import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@FeignClient(
        contextId = "RemoteNoteService",
        name = ServiceNameConstants.NOTE_SERVICE,           // "travel-note"
        fallbackFactory = RemoteNoteFallbackFactory.class    // 降级工厂
)
public interface RemoteNoteService {

    @GetMapping("/notes/feign/list")
    R<List<Note>> list(@RequestHeader(SecurityConstants.FROM_SOURCE) String source);

    @GetMapping("/notes/feign/{id}")
    R<Note> getOne(@PathVariable("id") Long id, @RequestHeader(SecurityConstants.FROM_SOURCE) String source);

    @GetMapping("/notes/viewnumTop")
    R<List<Note>> viewnumTop(@RequestParam("destId") Long destId);

    @GetMapping("/notes/bannerList")
    R<List<Note>> queryBannerList();

    @GetMapping("/notes/search")
    R<List<Note>> search(@RequestParam("keyword") String keyword,
                         @RequestParam(value = "limit", required = false) Integer limit);
}
```

**Feign 是什么？** 微服务之间互相调用的工具。比如目的地服务想查某目的地的游记，不用自己查数据库，而是通过 Feign 调 note 服务的接口。

#### 4.2.6 降级工厂：RemoteNoteFallbackFactory.java

```java
package cn.wolfcode.wolf2w.business.api.factory;

import cn.wolfcode.wolf2w.business.api.RemoteNoteService;
import cn.wolfcode.wolf2w.business.api.domain.Note;
import cn.wolfcode.wolf2w.common.core.domain.R;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.cloud.openfeign.FallbackFactory;
import org.springframework.stereotype.Component;

import java.util.List;

@Component
public class RemoteNoteFallbackFactory implements FallbackFactory<RemoteNoteService> {

    private static final Logger log = LoggerFactory.getLogger(RemoteNoteFallbackFactory.class);

    @Override
    public RemoteNoteService create(Throwable cause) {
        log.error("游记服务调用失败: {}", cause.getMessage());
        return new RemoteNoteService() {
            @Override
            public R<List<Note>> list(String source) {
                return R.fail("获取游记列表失败:" + cause.getMessage());
            }
            @Override
            public R<Note> getOne(Long id, String source) {
                return R.fail("获取游记详情失败:" + cause.getMessage());
            }
            @Override
            public R<List<Note>> viewnumTop(Long destId) {
                return R.fail("获取目的地游记失败:" + cause.getMessage());
            }
            @Override
            public R<List<Note>> queryBannerList() {
                return R.fail("获取推荐游记失败:" + cause.getMessage());
            }
            @Override
            public R<List<Note>> search(String keyword, Integer limit) {
                return R.fail("搜索游记失败:" + cause.getMessage());
            }
        };
    }
}
```

**降级是什么？** 当被调用的服务挂了或超时，不直接报错，而是返回一个友好的失败提示。就像打电话没人接，留个语音信箱而不是忙音。

#### Service 层：NoteServiceImpl.java

```java
@Override
public IPage<Note> queryPage(NoteQuery qo) {
    IPage<Note> page = new Page<>(qo.getCurrentPage(), qo.getPageSize());
    LambdaQueryWrapper<Note> wrapper = new LambdaQueryWrapper<>();

    // ① 前台/后台过滤逻辑
    // 前台只查公开游记（is_public 兼容 '1' 和 'true' 两种历史数据）
    // 后台不过滤，可查看草稿/待审核/拒绝的游记
    if (!Boolean.TRUE.equals(qo.getAdmin())) {
        wrapper.in(Note::getIsPublic, "1", "true");
    } else {
        if (qo.getStatus() != null) {
            wrapper.eq(Note::getStatus, qo.getStatus());
        }
    }

    // ② 目的地筛选
    if (qo.getDestId() != null) {
        wrapper.eq(Note::getDestId, qo.getDestId());
    }

    // ③ 作者筛选（我的游记）
    if (qo.getAuthorId() != null) {
        wrapper.eq(Note::getAuthorId, qo.getAuthorId());
    }

    // ④ 出发时间段筛选
    // travelTimeType 1-6 对应 1-2月、3-4月、5-6月、7-8月、9-10月、11-12月
    if (qo.getTravelTimeType() != null && !"-1".equals(qo.getTravelTimeType())) {
        int type = Integer.parseInt(qo.getTravelTimeType());
        int monthStart = (type - 1) * 2 + 1;
        int monthEnd = type * 2;
        wrapper.apply("MONTH(travel_time) BETWEEN {0} AND {1}", monthStart, monthEnd);
    }

    // ⑤ 人均花费筛选
    if (qo.getConsumeType() != null && !"-1".equals(qo.getConsumeType())) {
        switch (qo.getConsumeType()) {
            case "1": wrapper.between(Note::getAvgConsume, 1, 999); break;
            case "2": wrapper.between(Note::getAvgConsume, 1000, 6000); break;
            case "3": wrapper.between(Note::getAvgConsume, 6000, 20000); break;
            case "4": wrapper.ge(Note::getAvgConsume, 20000); break;
        }
    }

    // ⑥ 出行天数筛选
    if (qo.getDayType() != null && !"-1".equals(qo.getDayType())) {
        switch (qo.getDayType()) {
            case "1": wrapper.le(Note::getDays, 3); break;
            case "2": wrapper.between(Note::getDays, 4, 7); break;
            case "3": wrapper.between(Note::getDays, 8, 14); break;
            case "4": wrapper.ge(Note::getDays, 15); break;
        }
    }

    // ⑦ 排序
    if ("viewnum".equals(qo.getOrderBy())) {
        wrapper.orderByDesc(Note::getViewnum);        // 最热：浏览数倒序
    } else {
        wrapper.orderByDesc(Note::getCreateTime);     // 最新：创建时间倒序
    }

    return page(page, wrapper);
}
```

**LambdaQueryWrapper 是什么？** MyBatis-Plus 的条件构造器，用 Java 代码拼 SQL 的 WHERE 条件。
- `eq` = `WHERE 字段 = 值`
- `in` = `WHERE 字段 IN (值1, 值2)`
- `between` = `WHERE 字段 BETWEEN 值1 AND 值2`
- `ge` = `WHERE 字段 >= 值`
- `le` = `WHERE 字段 <= 值`
- `orderByDesc` = `ORDER BY 字段 DESC`
- `apply` = 直接拼原生 SQL（用于 MONTH() 等函数）

```java
import cn.wolfcode.wolf2w.business.api.domain.Note;
import cn.wolfcode.wolf2w.business.api.domain.NoteContent;
import cn.wolfcode.wolf2w.member.api.domain.UserInfo;
import lombok.Getter;
import lombok.Setter;
import java.io.Serializable;

/**
 * 游记详情 VO（继承 Note，避免手动扁平展开）
 * 继承 Note 所有基础字段，只需补充 VO 特有的扩展字段
 */
@Setter
@Getter
public class NoteDetailVO extends Note implements Serializable {

    private NoteContent content;        // 富文本内容
    private UserInfo author;            // 作者信息

    private Integer day;                // 出行天数别名（前端用 day 不是 days）
    private String personDisplay;       // 和谁旅游-中文展示文本

    private Boolean favorFlag = false;  // 是否已收藏
    private Boolean isFollow = false;   // 是否已关注作者
```

**为什么用继承而不是扁平展开？**

如果不用继承，VO 里要把 Note 的 20 多个字段（id、title、summary、coverUrl...）全部重新声明一遍，Service 里也要手动写 20 多个 `vo.setXxx(note.getXxx())`。

用继承后：
- VO 自动拥有 Note 的所有字段，不用重新声明
- Service 里用 `BeanUtils.copyProperties(note, vo)` 一行搞定，不用手动 set

#### Controller 层


#### Service 层：detail() 方法

```java
@Override
public NoteDetailVO detail(Long id) {
    Note note = getById(id);
    NoteDetailVO vo = new NoteDetailVO();
    if (note == null) {
        return vo;
    }

    // 1. 用 BeanUtils 拷贝 Note 所有基础字段到 VO
    //    VO extends Note，同名字段自动复制，不用手动写 20 多个 setXxx()
    BeanUtils.copyProperties(note, vo);

    // 2. 补 VO 特有的额外字段
    vo.setDay(note.getDays());                               // 前端用 day，提供别名
    vo.setPersonDisplay(mapPersonDisplay(note.getPerson())); // person 中文映射

    // 3. 富文本内容
    NoteContent nc = noteContentMapper.selectById(id);
    if (nc == null) {
        nc = new NoteContent();
        nc.setId(id);
        nc.setContent("");
    }
    vo.setContent(nc);

    // 4. 作者信息（Feign 调 member 服务查，失败用冗余字段兜底）
    if (note.getAuthorId() != null) {
        try {
            R<UserInfo> r = remoteUserInfoService.getOne(note.getAuthorId(), "inner");
            if (r != null && r.getCode() == R.SUCCESS) {
                vo.setAuthor(r.getData());
            }
        } catch (Exception ignored) {}
    }
    if (vo.getAuthor() == null) {
        // 兜底：Feign 挂了就构造匿名作者
        UserInfo fallback = new UserInfo();
        fallback.setId(note.getAuthorId());
        fallback.setNickname(note.getAuthorNickname() != null ? note.getAuthorNickname() : "匿名用户");
        fallback.setHeadImgUrl(note.getAuthorHeadImgUrl());
        fallback.setLevel(1);
        fallback.setState(0);
        vo.setAuthor(fallback);
    }

    // 5. 收藏 & 关注状态（默认 false，后续接入 Redis）
    vo.setFavorFlag(false);
    vo.setIsFollow(false);

    return vo;
}

/**
 * person 数字映射为前端展示文本
 */
private String mapPersonDisplay(String person) {
    if (person == null) return "";
    switch (person) {
        case "1": return "亲子出游";
        case "2": return "情侣出行";
        case "3": return "独自一人";
        case "4": return "家庭出行";
        case "5": return "和朋友";
        default:  return person;
    }
}
```

**`BeanUtils.copyProperties(source, target)` 原理**：把 source 和 target 中**字段名相同**的值自动复制过去。一行代码替代 20 多行手动 set。

**`r.getCode() == R.SUCCESS` 是什么？** 判断 Feign 调用是否成功。`R.SUCCESS = 200`。之前用了 `r.checkSuccess()` 但 R 类没这个方法，编译报错，改成这个写法。

#### Service 层

```java
@Override
@Transactional
public boolean saveNote(Note note, String content) {
    note.setCreateTime(new Date());
    note.setUpdateTime(new Date());
    // 状态分支：0 草稿 / 1 待发布（待发布才设发布时间）
    if ("0".equals(note.getStatus())) {
        // 草稿：不设 releaseTime
    } else if ("1".equals(note.getStatus())) {
        note.setReleaseTime(new Date());  // 待发布状态设置发布时间
    }
    save(note);  // MyBatis-Plus 自动入库，note.id 自动回填

    // 保存富文本内容（id 与游记 id 一致）
    NoteContent noteContent = new NoteContent();
    noteContent.setId(note.getId());  // 手动关联（NoteContent.id 不自增）
    noteContent.setContent(content);
    noteContentMapper.insert(noteContent);

    return true;
}

@Override
@Transactional
public boolean updateNote(Note note, String content) {
    note.setUpdateTime(new Date());
    if ("1".equals(note.getStatus()) && note.getReleaseTime() == null) {
        note.setReleaseTime(new Date());
    }
    updateById(note);

    NoteContent noteContent = new NoteContent();
    noteContent.setId(note.getId());
    noteContent.setContent(content);
    noteContentMapper.updateById(noteContent);

    return true;
}
```

**`@Transactional` 的作用**：保证 `save(note)` 和 `noteContentMapper.insert()` 在同一个事务中，要么都成功，要么都回滚。不会出现游记存了但内容没存的情况。

### 6.4 功能4：点赞 / 收藏 / 取消收藏

#### 前端需要什么？

```
POST /notes/star/16         → 点赞（thumbsupnum + 1）
POST /notes/collect/16      → 收藏（favornum + 1）
POST /notes/uncollect/16    → 取消收藏（favornum - 1）
```

#### Controller 层

```java
@RequiresLogin
@PostMapping("/star/{id}")
public R<?> star(@PathVariable Long id) {
    noteService.lambdaUpdate()
            .eq(Note::getId, id)
            .setSql("thumbsupnum = COALESCE(thumbsupnum, 0) + 1")
            .update();
    return R.ok();
}

@RequiresLogin
@PostMapping("/collect/{id}")
public R<?> collect(@PathVariable Long id) {
    noteService.lambdaUpdate()
            .eq(Note::getId, id)
            .setSql("favornum = COALESCE(favornum, 0) + 1")
            .update();
    return R.ok();
}

@RequiresLogin
@PostMapping("/uncollect/{id}")
public R<?> uncollect(@PathVariable Long id) {
    noteService.lambdaUpdate()
            .eq(Note::getId, id)
            .gt(Note::getFavornum, 0)
            .setSql("favornum = favornum - 1")
            .update();
    return R.ok();
}
```

**`COALESCE(thumbsupnum, 0)` 是什么？** SQL 函数，如果字段为 NULL 就当 0 处理。防止 NULL + 1 = NULL 的问题。

**`lambdaUpdate()` 是什么？** MyBatis-Plus 的链式更新，直接用 Java 代码写 `UPDATE ta_note SET thumbsupnum = thumbsupnum + 1 WHERE id = ?`，不用去 Mapper 写 SQL。

#### Service 层

```java
@Override
public List<Note> queryBannerList(int limit) {
    // 近2个月内创建、公开的游记，按收藏数倒序取前 N

    Calendar calendar = Calendar.getInstance();

    Date twoMonthsAgo = calendar.getTime();
    return lambdaQuery()
            .in(Note::getIsPublic, "1", "true")
            .ge(Note::getCreateTime, twoMonthsAgo)
            .orderByDesc(Note::getFavornum)
            .last("limit " + limit)
            .list();
}

@Override
public List<Note> queryByDestId(Long destId, int limit) {
    return lambdaQuery()
            .eq(Note::getDestId, destId)
            .in(Note::getIsPublic, "1", "true")
            .orderByDesc(Note::getThumbsupnum)
            .last("limit " + limit)
            .list();
}
```

**`lambdaQuery()` 是什么？** MyBatis-Plus 的链式查询，等价于 `new LambdaQueryWrapper<>()` 但写法更简洁。`.list()` 表示返回列表。

```java
public List<Note> search(String keyword, Integer limit) {

    return lambdaQuery()
            .in(Note::getIsPublic, "1", "true")
            .and(w -> w.like(Note::getTitle, keyword)

                    .like(Note::getSummary, keyword))

            .last(limit != null ? "limit " + limit : "")
```

### 6.9 功能9：前端路径兼容（TravelsAliasController）

#### 为什么需要这个 Controller？

前端有些请求路径不以 `/notes` 开头，但网关统一前缀 `/note` 会把它们路由到 note 服务。比如：
- `GET /note/travels/user/query` → 我的游记（路径前缀是 travels 不是 notes）
- `GET /note/destinations/regions` → 写游记时选区域（路径前缀是 destinations）

这些路径放不进 `NoteController`（前缀 `notes`），所以单独建一个 Controller。

#### Controller 层

```java
@RestController
public class TravelsAliasController {

    @Autowired
    private INoteService noteService;
    @Autowired
    private RemoteRegionService remoteRegionService;

    /** 我的游记 —— 前端 GET /note/travels/user/query */
    @GetMapping("/travels/user/query")
    public R<IPage<Note>> myTravels(NoteQuery qo) {
        Long currentUserId = null;
        try {
            currentUserId = SecurityUtils.getUserId();
        } catch (Exception ignored) {}
        if (qo.getAuthorId() == null && currentUserId != null) {
            qo.setAuthorId(currentUserId);
        }
        return R.ok(noteService.queryPage(qo));
    }

    /** 写游记-区域列表 —— 前端 GET /note/destinations/regions */
    @GetMapping("/destinations/regions")
    public R<List<Region>> regions(@RequestParam(required = false) Long ishot) {
        R<List<Region>> r = remoteRegionService.list("inner");
        if (r == null || r.getCode() != R.SUCCESS || r.getData() == null) {
            return R.ok(Collections.emptyList());
        }
        List<Region> data = r.getData();
        if (ishot != null && ishot == 1L) {
            data = data.stream()
                    .filter(e -> e.getIshot() != null && e.getIshot() == 1L)
                    .collect(Collectors.toList());
        }
        return R.ok(data);
    }
}
```

### 8.2 内部调用安全机制

Feign 内部调用通过 `@InnerAuth` 注解 + `from-source=inner` 请求头标识，确保接口仅允许微服务内部调用：

```java
// 被调用方：加 @InnerAuth，外部请求进不来
@InnerAuth
@GetMapping("/feign/{id}")
public R<Note> feignGet(@PathVariable Long id) {
    return R.ok(noteService.getById(id));
}

// 调用方：传 source = "inner"
R<Note> r = remoteNoteService.getOne(id, SecurityConstants.FROM_SOURCE);
```

### 8.3 判断 Feign 调用是否成功

项目 `R` 类没有 `checkSuccess()` 方法，用 `getCode() == R.SUCCESS` 替代：

```java
// ❌ 编译报错：R 类没有 checkSuccess() 方法
if (r != null && r.checkSuccess()) { ... }

// ✅ 正确写法
if (r != null && r.getCode() == R.SUCCESS) { ... }
// R.SUCCESS = 200
```

## 9. 本次会话踩坑总结

### 9.1 `orderBy` 参数类型转换错误

**现象**：
```
Failed to convert property value of type 'java.lang.String' to required type 'java.lang.Integer' for property 'orderBy'
```

**原因**：前端传 `orderBy=viewnum`（字符串），但 NoteQuery 中 orderBy 是 `Integer` 类型，SpringMVC 自动转换失败。

**解决**：把 NoteQuery 的 `orderBy` 改为 `String` 类型，Service 层用 `"viewnum".equals(qo.getOrderBy())` 判断。

**教训**：Query 对象的字段类型要和前端传参一致，前端传字符串就写 String，不要想当然写 Integer。

---

### 9.2 `checkSuccess()` 方法不存在

**现象**：编译报错 `找不到符号 checkSuccess()`

**原因**：参考了若依框架其他项目的写法，但本项目的 `R` 类没有封装 `checkSuccess()` 方法。

**解决**：全局替换为 `r.getCode() == R.SUCCESS`（本质就是判断 code 是否等于 200）。

**教训**：复制别的项目代码时，要确认方法是否存在。不确定的方法用 IDEA 点进去看源码。

---

### 9.3 `Unknown column 'author_nickname'` 数据库字段不存在

**现象**：
```
Unknown column 'author_nickname' in 'field list'
```

**原因**：Note 实体加了 `authorNickname` 字段，但数据库 `ta_note` 表没加这个列，MyBatis-Plus 自动把它拼进 SELECT 语句就报错了。

**解决**：给字段加 `@TableField(exist = false)`，告诉 MP "这个字段不在数据库里，生成 SQL 时别带上"。

**教训**：实体类有字段 ≠ 数据库有列。新增字段后要同步加列，或者用 `@TableField(exist = false)` 标记为非数据库字段。

---

### 9.4 `getContent()` 方法找不到

**现象**：编译报错 `找不到符号 getContent()`

**原因**：NoteController 的 `/add` 接口调了 `note.getContent()`，但 Note 实体没有 `content` 字段（富文本内容存在独立的 NoteContent 表）。

**解决**：在 Note 实体加一个非数据库字段 `@TableField(exist = false) private NoteContent content;`，专门用来接收前端传参。

**教训**：前端传的 JSON 字段，后端实体里一定要有对应字段接收，否则 SpringMVC 无法反序列化。

---

### 9.5 Mapper 找不到 Bean

**现象**：IDEA 报 `无法自动装配，找不到 'NoteContentMapper' 类型的 Bean`

**原因**：Mapper 接口缺少 `@Mapper` 注解。

**解决**：给每个 Mapper 接口加 `@Mapper` 注解。

**教训**：虽然 `@MapperScan` 也能扫描，但加上 `@Mapper` 更明确，避免环境差异导致的 Bean 注入问题。

---

### 9.6 列表页面空白 / 数据不显示

**现象**：接口能调通但 records 为空

**原因**：
1. 历史数据 `is_public` 有 `'1'` 和 `'true'` 两种值，查询只过滤 `'1'` 漏了 `'true'`
2. 历史数据 `status` 全为 `'0'`（草稿），但查询条件过滤了 `status='2'`（审核通过）
3. 历史数据 `release_time` 全为 NULL，排序用 `release_time` 导致结果异常

**解决**：
- 查询条件改用 `is_public IN ('1', 'true')` 兼容两种值
- 前台查询去掉 `status='2'` 过滤（历史数据都是草稿状态）
- 排序改用 `create_time` 而非 `release_time`

**教训**：开发前先看数据库真实数据，不要只看建表语句。历史数据可能和设计文档不一致。

---

### 9.7 前端模板字段名不匹配

**现象**：详情页数据有了但前端渲染不出来

**原因**：前端模板用 `detailData.day`（单数），但后端 Note 实体是 `days`（复数）；前端用 `detailData.content.content`（嵌套），但后端返回的是 `detailData.content`（字符串）。

**解决**：
- VO 里加 `private Integer day;` 作为 `days` 的别名
- VO 的 content 字段类型改为 `NoteContent` 对象（含 `content` 属性），而不是 String

**教训**：前后端联调时，先确认前端模板期望的数据结构，再决定后端 VO 怎么设计。

---

### 9.8 VO 继承方式 vs 扁平展开

**现象**：NoteDetailVO 最初手动声明了 20 多个和 Note 重复的字段，Service 里手动 set 了 20 多行，代码冗余。

**解决**：NoteDetailVO 改为 `extends Note`，Service 里用 `BeanUtils.copyProperties(note, vo)` 一行搞定。

**对比**：

| 对比项 | 扁平展开（旧） | 继承 + BeanUtils（新） |
|--------|---------------|----------------------|
| VO 字段数 | 20+ 个重复字段 | 只写 6 个特有字段 |
| Service 代码 | 24 行手动 set | 1 行 copyProperties |
| 新增字段时 | VO + Service 都要改 | 只改 Entity |
| 出错概率 | 容易漏字段 | 自动复制不怕漏 |
