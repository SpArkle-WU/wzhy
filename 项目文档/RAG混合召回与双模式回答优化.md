# 基于 ES 的混合召回与双模式回答优化

> 面试回答完整版，适用于 3-5 分钟的技术深挖场景。

---

## 背景

我负责的是旅游攻略智能问答系统的 RAG 全流程落地。系统基于 Spring Cloud 微服务架构，用 ES 做向量存储和检索，接入阿里云通义千问的 Embedding 和 Chat 接口。用户提问后，系统从攻略知识库中检索相关片段，拼入 Prompt 交给 LLM 生成回答并标注来源。上线后经历了两轮核心优化。

---

## 第一轮：混合召回——解决单路检索的召回盲区

### 问题

最初只用了 KNN 向量检索，上线后发现一个典型问题——用户搜"长隆"这种精确关键词时，向量召回可能把语义相近但不含该关键词的攻略排在前面，反而把真正命中关键词的攻略挤掉。纯语义检索对专有名词、地名等精确匹配场景有盲区。

### 方案

加了一路 BM25 关键词召回，两路并行检索后通过 RRF 融合排序。

**BM25 那路：** 用 `multi_match` 查 `title` 和 `content` 两个字段，title 加权 2 倍。因为标题通常比正文更能概括攻略主题，匹配到标题的文档应该排更前。字段映射用的是 `ik_max_word` 中文分词器，保证"长隆野生动物园"能被正确分词匹配。

**KNN 那路：** 走 ES 的 `dense_vector` 字段 + cosine 相似度，把用户问题 Embedding 后做 KNN 查询，捕获语义近似但关键词不同的文档。

**RRF 融合：** 两路各召回 `topK*2` 的候选，然后用 Reciprocal Rank Fusion 做分数融合。公式是 `score(d) = Σ 1/(k + rank_i(d))`，k 取 60。一个文档在两路中排名越靠前、出现次数越多，融合分数越高。比如某篇攻略在 BM25 排第 1、KNN 也排第 3，它的融合分就会比只在单路排第 1 的文档高，因为它得到了双路验证。

**一个工程细节：** RRF 我是在应用层手动实现的，没有用 ES 8.8+ 的原生 RRF 查询语法，因为项目 ES 版本不支持。手写也就几十行代码，而且灵活度更高——后续如果要做加权融合或者加第三路召回都很方便。

### 效果

关键词精确匹配和语义近似互补。像"长隆"这种精确词靠 BM25 兜底，"带孩子去哪玩"这种语义泛化查询靠 KNN 兜底，单路都会漏的场景双路覆盖了。

## 第二轮：双模式回答——解决幻觉性引用

### 问题

混合召回解决了召回率，但暴露了一个更严重的问题。用户问"你是谁"，系统居然返回了旅游攻略并附带来源引用——"来源: strategy-2-0"、"来源: strategy-18-0"。根因有两层：

1. **检索层：** 向量检索无条件取 topK 条，不管问什么都返回语义最近的几条。"你是谁"和任何攻略都不相关，但 KNN 仍会返回距离最近的 5 条。
2. **生成层：** 提示词强制要求"只能依据资料回答并必须引用来源"，模型被迫把不相关攻略硬凑成证据。

**核心认知：检索到但不相关，比检索不到更危险。** 因为前者会让用户误以为答案有依据，产生幻觉性引用，严重损害系统可信度。

### 方案

没有用分数阈值过滤，改成了显式双模式回答。

**为什么不用阈值？** 不同类型问题的语义距离差异很大。"广州亲子游攻略"和攻略内容的语义距离，跟"你是谁"和攻略内容的语义距离，两者分布完全不同，一个固定阈值不可能同时适配两类场景，容易误杀正常查询。所以让 LLM 来判断相关性，比数值规则更鲁棒。

**双模式具体实现：** 每次检索后，把用户问题和检索到的攻略片段一起交给 LLM，在 Prompt 中明确指示模型先判断相关性再选择回答模式：

- **知识库模式：** 问题与攻略语义相关 → 基于攻略内容作答，附带真实来源引用。
- **通用 AI 模式：** 问题与攻略不相关，或检索结果为空 → 直接回答，不附加任何攻略来源。

服务端根据模型输出的 mode 字段决定是否渲染来源引用区域，前端同步展示当前回答的来源模式，让用户明确知道这个回答是来自知识库还是 AI 通用回答。

### 验证

用了两个边界用例做端到端验证——"你是谁"（无知识库内容）走通用 AI 模式正常回答，"广州适合带孩子去哪里玩"（有知识库内容）走知识库模式引用真实攻略来源，两类场景都正确覆盖。

---

## 总结

这两轮优化针对的是不同层面的问题：混合召回解决的是**召回率**——"该召回的没召回"；双模式回答解决的是**可信度**——"不该引用的硬引用"。一个在召回层，一个在生成层，两者配合让系统既不漏召回、也不乱引用。

---

## 追问延伸

**Q: RRF 的 k 值为什么取 60？**

这是论文推荐值，控制排名靠后文档的得分衰减速度。k 越大，排名靠后的文档得分衰减越慢，越能体现"双路命中"的加权效果；k 越小越偏向排名靠前的文档。60 是经验最优值。

**Q: 双模式会不会增加延迟？**

不会额外多一轮 LLM 调用，相关性判断和回答生成在同一次请求中完成，Prompt 指示模型先判断再回答，输出中携带 mode 字段。

**Q: 后续如何扩展？**

如果数据量上亿级，ES 的 KNN 性能会下降，可以引入 Milvus 做专用向量检索层，ES 退回负责 BM25 关键词召回，两路仍然通过 RRF 融合，架构层面平滑切换。
